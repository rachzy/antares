# Contributing

## Commits

- Use a `type: message` subject (`feat`, `fix`, `refactor`, `docs`, `style`, `chore`, `test`).
- Keep commits focused and never commit generated code or local scratch (`plans/`, `.superpowers/`, `.data/`).

## Pull requests

- Open the PR against `main` and keep it to one change.
- The description has a single **Summary** section: a bullet list with one brief sentence per major or minor change, easy to read at a glance.
- Do not credit AI tools or assistants anywhere in the description.

## Before you open a PR

```sh
npm run format
npm run lint
npm run test
```
